What’s new in Microsoft Intune at Ignite

Saved for offline reading · Open original ↗

The IT teams today are under pressure. As employees adopt AI tools and build their own agents to elevate productivity, IT must secure and govern where AI runs, what it can access, and what it can do. At the same time, AI-driven vulnerabilities expose security gaps at a rate that could outpace the best Security and IT teams. The challenge is no longer just enabling AI safely; it’s closing those gaps across a growing digital estate fast enough to stay ahead.

This week at Microsoft Ignite, we are unveiling new Microsoft Intune capabilities to help IT meet those challenges head-on. From securing the environments where AI runs to reducing exposure across the digital estate, these capabilities give administrators new ways to simplify management while protecting company data.

AI is changing the physics of cybersecurity: agents are becoming a new class of insider threat actor. Attacks are becoming autonomous, and existing security gaps are amplified at machine speed. For IT, that means turning AI governance goals into practical controls for agent access, execution environments, and company resources.

Securing AI starts with visibility into the agents running in your environment, including those IT hasn’t approved. Microsoft Agent 365 brings together detection capabilities from Microsoft Defender, Microsoft Entra, and Intune to help identify those agents. With Intune's new software compliance policy, available in public preview, IT can mark Windows devices running specified unsanctioned agents as noncompliant and use Conditional Access to block access to corporate resources. Users can then be guided to remove the unwanted agents and bring their devices back into compliance.

 

Figure 1: Configure software compliance policies in Microsoft Intune by identifying restricted applications using MSI product codes.

Protecting corporate resources isn’t just about restricting unwanted agents. It’s also about giving organizations the confidence to adopt approved AI apps. Leading AI apps and providers, including Microsoft Copilot, GitHub Copilot, Anthropic Claude, and Open AI ChatGPT, have already integrated the Intune SDK so organizations can apply app protection policies to their AI app management. Organizations can extend the same consistent protection they use for work data to these apps, helping them meet governance requirements as AI adoption grows.

The Microsoft approach for endpoint AI management is built on identity, containment, and governance. For supported agents, Intune is rolling out new policies for Microsoft Execution Containers (MXC) that allow IT to set guardrails for container file and network access. These controls help organizations run approved agents using MXC containers with administrator defined boundaries. Microsoft is continuing to expand coverage and enforcement, so these protections can apply across more agent scenarios while keeping administrator policies in effect.

 

Figure 2: Configure agent containment boundaries in Microsoft Intune to control AI agent access to files, directories, and network resources.

For a deeper look at how IT can manage the security layers across agents on endpoints, watch Manage and Govern AI Agents on Windows as Your Trusted Execution Layer (BRK391) and read our blog exploring software compliance and the broader endpoint-management approach to governing AI agents.

For a broader perspective on securing the agentic era, see the Microsoft Security Ignite blog. It examines how organizations can govern AI and agents across the security stack, from endpoint visibility and access controls to data protection and risk response.

Beyond securing AI, IT must defend against attackers who use AI to find vulnerabilities and accelerate attacks. Reducing exposure means strengthening protections from the start, keeping apps and devices current, and turning prioritized risks into coordinated action.

At Microsoft Ignite, we are advancing Microsoft Perception with a set of green team agents including the Risk Reduction, Vulnerability Remediation, and Shielding agents to help security and IT teams assess exposure, prioritize risks, and coordinate mitigation and remediation. The Intune Vulnerability Remediation Agent, in limited public preview, combines Defender vulnerability intelligence with Intune device and app context to build and execute agentic remediation playbooks for prioritized risks. These playbooks enable automated application and OS patching, connecting risk discovery to automated remediation on Intune managed devices. The Vulnerability Remediation Agent is available within Perception as part of the Reduce Risk Exposure playbook and in the Intune admin center for IT to run at any time.

 

Figure 3: Create AI-assisted vulnerability remediation plans in Microsoft Intune to streamline app selection, device assignments, deployment, and progress monitoring.

The server estate is a high-value target for attackers, so managing and protecting Windows Servers consistently is an important part of reducing exposure across your estate. Windows Server management in Intune, in Insider preview, brings eligible servers into the same cloud-management workflows your endpoint team already uses. That includes edge and branch servers and persistent virtual desktop sessions. It extends proven tools for configuration, app deployment, and compliance to supported server scenarios. It also incorporates Windows Autopatch for update management, so IT can manage updates for eligible servers and Windows clients in one familiar place. This helps reduce exposure from outdated software and inconsistent settings, while device compliance and identity controls govern access to corporate resources. Azure Arc continues to complement Intune for infrastructure governance and operations.

 

Figure 4: View a list of enrolled Windows and Windows Server devices in Intune admin center.

To learn more, you can try this Windows Server Management preview in a non-production environment with Windows Server Insider Preview builds and read the latest blog on Windows Server with Microsoft Intune.

Keeping apps current starts with knowing what is installed. IT can use device-level app inventory (now in public preview) to provide richer application details and inventory reporting. For ongoing maintenance, Enterprise Application Management (EAM) is expanding automatic updates, in private preview, to more eligible and verified Windows apps, including those IT did not originally deploy. New EAM update policies keep eligible apps current without manual update packaging or a separate policy for every app. Intune EAM brings the same always-current model IT already relies on for Windows to the apps employees use every day.

Complementing automatic updates and app inventory, App in-use detection, in private preview, helps IT identify when a running application could block an app installation and control what happens next. Administrators can report the blocked installation or configure processes to close it, with or without user notification. This helps teams address installation blockers and keep app updates moving.

Effective exposure management goes beyond patching software. It also requires identifying configuration weaknesses and prioritizing gaps for remediation. In Intune Advanced Analytics, we are adding Center for Internet Security (CIS) benchmark auditing, in public preview this November, to help IT build on the existing Defense Information Systems Agency Security Technical Implementation Guide (DISA STIG) auditing experience. Administrators can assess device groups against these benchmarks and use per-check results to identify gaps, prioritize corrective action, and track alignment over time. Both experiences enable IT to audit configurations without changing device settings.

 

Figure 5: Microsoft Intune security baseline audit results showing how many devices pass a CIS Windows 11 benchmark setting.

As threats accelerate and the estate changes, IT and security teams need faster ways to turn signals into action. The new AI-powered Microsoft Perception experience, in limited public preview in Intune, turns plain-language questions into multi-step investigations across your environment. Administrators describe what they need, and the experience builds complex, multi-step plans across data sources. It writes and runs queries, calls the appropriate APIs, and combines the results. It also explains each step with citations, so administrators don’t need to write queries or know which APIs to call. IT can explore device and security signals, assess the scope of an issue, and review the underlying queries.

 

Figure 6: Use AI-powered insights in Microsoft Intune to identify risky users in your environment.

Administrators can also refine results in conversations by filtering, adding columns, and correlating data. Results can then be saved as new Custom Reports with data views and advanced visualizations all in one place. These repeatable checkpoints help teams track changes, monitor key insights, confirm whether exposure is shrinking, and check that remediation reached devices. To act on findings, administrators can add affected devices or users to a new or existing group and follow through with familiar Intune tools. This experience is available to Intune customers onboarded to Microsoft Perception. Check out our blog for a deep dive into rethinking work and reducing risk.

 

Figure 7: Save results into custom reports to monitor key insights all in one place.

Underlying Intune platform improvements support these investigations and reports by moving device data closer to near real time. Read more about Intune’s journey to faster device management here. On Windows, faster app inventory and policy reporting help teams see changes sooner, while timestamps make data freshness clear. Broader inventory coverage, including new support for registry key and file inventory, gives administrators and AI-powered experiences a more complete view of the estate. Related improvements to Remote Help Diagnostic Data Reports for Windows give admins richer device context during support sessions. See the blog for a deeper look.

The same attention to improving admin experiences in Intune extends to employees setting up a device. In Intune, we have introduced a more transparent Windows Autopilot device preparation experience in limited public preview. On supported deployments, the Intune Company Portal app opens automatically after the Out‑of‑Box Experience (OOBE) stage to show device compliance and application installation status. Employees can see what’s complete, what remains in progress or pending, and when onboarding setup is finished.

 

Figure 8: Enable users to track compliance and app installation status in a non-blocking experience in Company Portal.

AI is expanding both what IT can enable and what IT must protect. With these announcements, Intune is helping IT govern agents and the environments where they run, reduce exposure through ongoing maintenance and targeted remediation, and extend familiar management to more of the estate. New AI-powered experiences help administrators turn complex signals into clearer next steps, while improvements to everyday workflows support IT and employees alike. Together, these capabilities help you stay in control.
