Build faster, trusted remote support with Diagnostic Data Reports in Remote Help

Saved for offline reading · Open original ↗

By: Kara Wang | Product Manager 2, Microsoft Intune & Ingrid Allen | Senior Product Manager, Windows

Support sessions are most effective when your helpdesk team can quickly start with the right device context. In many cases, helpdesk staff still need to confirm key system details with the user before moving into targeted troubleshooting.

In attended Windows support sessions, Diagnostic Data Reports in Remote Help for Windows is now available to help quickly onboard helpdesk staff with device information while maintaining user trust. In this context, attended sessions are sessions where the user participates and grants helpdesk staff access. These sessions support view only access, full control, and optional User Account Control (UAC) elevation. This capability is currently not available for Windows Remote Help unattended sessions.

With this feature, your helpdesk team can request diagnostic data directly in the Remote Help session and generate a Diagnostic Data Report to guide troubleshooting. If updated information is needed, the helpdesk staff can refresh the report during the session. The user decides whether to allow sharing, can view what is shared, and can stop sharing at any time. Helpdesk staff receive practical context for faster, more informed troubleshooting, and the user keeps clear control.

Figure 1: Remote Help session with Diagnostic Data Reports available to helpdesk staff.

When your team starts with structured diagnostic context, helpdesk staff spend less time on discovery and more time on resolution. That improves first pass troubleshooting and reduces repeat clarifying questions.

You also keep the consent model transparent:

  • The user explicitly allows or declines sharing.
  • The user can see the shared data.
  • The user can stop sharing during the session.

This balance helps you improve support speed while maintaining confidence in your remote support process.

  1. For attended Windows device sessions, the helpdesk staff requests diagnostic data collection by selecting the icon in the Remote Help toolbar.
    Figure 2: Helpdesk staff requests a Diagnostic Data Report.
  2. The user sees a request asking permission for the helpdesk staff to view and possibly store their device diagnostic data.
  3. The user chooses Allow or Decline.
    Figure 3: Device user consent prompt for diagnostic data sharing.

If the user selects Allow:

  • The helpdesk staff sees a report with collapsible sections with options to Refresh, Copy, and Collapse All.
  • A View Shared Data button appears on the user’s toolbar.
  • When the user selects View Shared Data, the diagnostic panel appears in the Remote Help app.
  • The same diagnostic data report is shown to the helpdesk staff and the user.

If the user selects Decline, helpdesk staff is notified. If the user initially allows the report to be generated and later chooses to turn sharing off, helpdesk staff is notified that the user stopped sharing data.

When the user allows sharing, the report organizes data into practical categories. These categories help your helpdesk staff move from collecting context to resolving issues.

Diagnostic Data Reports give your helpdesk staff a reliable snapshot of device state to guide each troubleshooting step.

  • Diagnostic values are captured as a point in time snapshot.
  • Metrics like memory, CPU, and network activity reflect device state at collection time.
  • After a change, the helpdesk staff can refresh to collect a current snapshot and validate whether remediation changed the device’s state.
  • If a field is missing, this means that the device did not report that value. It does not mean healthy, false, or zero by default.

This gives your helpdesk staff a clearer context for decision making and helps keep troubleshooting steps grounded in current, observable device data.

Users can inspect what was shared by selecting View Shared Data after they allow sharing. This helps maintain transparency during the session.

If sharing is turned off, previously collected information remains visible for reference, but refreshing data is unavailable until sharing is turned back on. If the user resumes sharing, the helpdesk staff can refresh to collect a current snapshot.

This model lets you keep troubleshooting continuity while respecting user control.

A user reports choppy screen sharing and delayed remote control, even though their connection appears healthy. The helpdesk staff can spend time validating connectivity with separate checks and still struggle to determine whether the issue is network congestion or endpoint resource contention.

With Diagnostic Data Reports in Remote Help, the helpdesk staff requests the report and reviews Network, Performance, and GPU together in real time. The helpdesk staff confirms stable link speed and normal send and receive throughput but also sees elevated CPU and GPU pressure during the session. This indicates an endpoint bottleneck rather than a bandwidth problem. The helpdesk staff guides the user to close high impact apps and reduce display and graphics load, then refreshes the report to confirm improved responsiveness.

The result is faster confirmation of whether lag is network related or endpoint related, fewer unnecessary escalations to network teams, and quicker in session recovery with immediate validation after each fix.

Diagnostic Data Reports are rolling out now and expected to be available to all Intune customers by mid-December, so give them a try in your next Windows attended session and see how much time they save you.
